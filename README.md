# Super Auto Pets · 单机 + 局域网联机

一个纯前端的 Super Auto Pets 复刻。**双击 `index.html` 就能玩**，不需要安装任何东西。
想和朋友一起玩时，双击 `开服.bat` 就能开一个局域网房间。

---

## 怎么玩

### 三种打开方式

| 你想干嘛 | 怎么做 | 要服务器吗 |
|---|---|---|
| **自己玩** | **双击 `index.html`** → 选模式 → 开玩 | 不要 |
| **和朋友在同一局里玩** | 主机双击 **`开服.bat`** → 把它显示的局域网地址发给大家 → 大家浏览器打开加入房间 | 要（就是主持人的电脑） |
| **发个链接让别人自己玩** | 把这个文件夹传到任意静态托管，把链接发出去 | 不要 |

第三种之所以不需要服务器：单机模式本来就是纯静态的。但**公网链接上不能联机** ——
联机需要一个"大家一起连的服务器"，公网静态托管只发文件、不会算游戏。
所以主页会自动探测：探测到服务器才显示「🌐 联机混战」入口。

### 四种模式

| 模式 | 玩法 | 经济 |
|---|---|---|
| **🎯 经典模式** | **10 胜**通关、**3 败**出局（平局不算输）。每回合打一支系统生成的对手队伍 | **SAP 式**：每回合固定 10 金，**不累积**；宠物统一 3 金；刷新 1 金 |
| **📅 每日挑战** | 经典模式，但**种子由日期决定** —— 同一天所有人玩的是同一局。可反复重玩，记录首次成绩和最好成绩 | 同经典模式 |
| **⚔️ 8 人混战** | 你和 **7 个人机**同场竞技。每回合随机两两配对，输的扣血，**血量归零出局**；活到最后获胜 | **TFT 式**：基础 5 金 + **利息**（每存满 10 金 +1，上限 5）+ **连胜奖励**（分档 +1/+2/+3），金币**累积**；宠物**按星级定价** T1=1 金 … T6=6 金；刷新 2 金 |
| **🌐 联机混战** | 8 人混战，但**其他座位可以是真人**。人不够时剩下的座位由电脑补位 | 同 8 人混战 |

### 宠物包

主页顶部可以选**用哪个包开这一局**，三个模式都跟着走：

| 包 | 只数 | 说明 |
|---|---|---|
| 🐢 **龟包** | 61 | 官方 Turtle Pack Tier 1–6 全部（含安眠药） |
| ⭐ **星包** | 77 | 官方 Star Pack **76 只里已完成 73 只** + 4 只新版本追加（见下方「星包进度」） |

**为什么一局只用一个包**：两个包混进同一个池子会把重复率砍半，
而 SAP 的升级完全依赖反复出现同名宠物 —— 混池会让合成升级变得几乎不可能。
官方的食物池也是按包独立的（星包**没有**苹果、蜂蜜、西瓜，它的食物是
草莓/黄瓜/奶酪/葡萄/胡萝卜/胡椒/爆米花），这一点也照做了。

联机时包由**服务器**决定：`node server.js --pack=star`。

#### 第 14 轮：变身（transform）原语 + 菊石 / 仙犰狳

这轮加了两个**新引擎原语**，一次解锁了两只宠物：

**1. `transform`（变身）** —— `Battle.transform` / `ShopEnv.transform`
- 保留 `uid`（否则回放对不上同一个格子）、保留已吃到的属性加成、等级重置为 1、不会致死
- 回放层新增 `transform` 事件处理（见 `star14c_playback.js` 的专门测试）
- 用在：**菊石**阵亡把身后的友方变成**拟态章鱼**；**仙犰狳**受伤后变成**仙球**

**2. `permBuff`（战斗内永久加成回写商店）** —— `Battle.buffPerm` + `applyPermBuffs`
- 战斗跑在队伍**副本**上，所以「永久 +2 生命」这种效果必须靠事件回写：
  引擎发 `permBuff` 事件，`Game.resolveTurn` 按 `uid` 找回商店里的真实宠物再加
- ⚠️ 三个跑战斗的地方都要调：经典模式、8 人混战、联机（都已接上）
- 用在：**仙犰狳**「若还活着，永久 +2 生命」

新增的两只（都在官方 76 里）：
- **菊石 Ammonite** T6 5/3 —— 阵亡：把**身后**的友方变成 1 级拟态章鱼。
  官方 v0.41 把「把最前面 N 个友方变成蝴蝶」改成了这个版本，本作跟当前官方走。
  「每刷新 2 次给 +N 经验」只在**战斗中**结算（官方原文 "in battle"）——
  所以拿安眠药在商店里杀菊石时只会变身、不给经验。

#### ⚠️ 两个查资料时踩到的坑（值得记下来）

### 实测反馈修复 · 第二批（第 16 轮）

用户又玩了一轮，报的第二批问题。同样是**每一条都回头检查另外两个模式**。

#### 🐛 又抓到两个"静默失效"的 bug

- **「训练场」遗物一直是白板！**（三个模式都中招）
  `applyRelicTurnStart` 传进去的 `g` 是 **ShopEnv**，而 `ShopEnv.team` 是个
  **方法**（`team(side)` 返回队伍数组），所以遗物里写的 `g.team[0]` 拿到的是
  `undefined`，`buff()` 又对 `undefined` 静默 return —— 抽到它等于白抽。
  现在统一用 `relicTeamOf(g)` 取队伍，并加了注释说明这个坑。
- **「急救包」和「战旗」完全重复，而且描述和实现对不上**。
  它的说明写的是「每场战斗结束后回复 2 生命」，但本作战斗跑在队伍副本上、
  属性根本不回写商店，所以那句话**不可能实现**；实现上退化成了「开战时全队 +2 生命」，
  和战旗（+4 生命）只是数值不同。现在改成一条真正独立的效果：
  **每回合开始全体 +1 生命（永久）**，和训练场「只加最前排」互补，标签也从「战斗」挪到「成长」。

#### 🐛 升星奖励会冲掉冻结的宠物

`tierUpReward`（商店升级时免费刷 2 个「下一星级」宠物）原来是**纯随机挑 2 个格子**，
完全不管那格是不是被玩家冻结了，还会把冻结标记一起清掉 —— 玩家会莫名其妙丢东西。
现在**优先用没被冻结的格子**（空格也算），不够才动冻结的。

#### ✨ 商店摆不下的道具不再丢失（"🎒 待用"）

商店只有 2 个食物位，而「3 级鸽子库存 3 个免费苹果」这种会多出来。
之前第 3 个会**覆盖掉一个**，等于凭空丢东西（用户实测 2 级鸽子只拿到 1 个）。
现在多出来的会进 **🎒 待用库存**，显示在食物区下面，**食物位一空出来就自动补上**，
一个都不会浪费。实测 3 级鸽子现在真能吃到 3 个苹果。

> 顺带确认：**只有鸽子和鼠妇**会「按等级库存 N 个」，
> 其余 4 只（虫子 / 小鼠 / 红雀 / 乌鸦）每次只塞 1 个，不受影响。

#### 🎮 玩法说明改成「按钮 + 分模块弹层」

原来挤在主页上（为了让篇幅短，只能砍内容）。现在收进一个按钮，
点开是像图鉴那样的弹层，里面分 **7 个模块**：基础流程 / 宠物与合成 /
商店与等级 / 道具与标记 / 战斗机制 / 阵营羁绊 / 四个模式。
篇幅放开了，表格、数值、常见误区都能写清楚。

#### ⚖️ 羁绊平衡 + 新增 2 个阵营

用户反馈「小兽和爬行明显比其他强」（同样 2 只对战）—— 确实：
**2 只的低门槛 + 全队拿西瓜（减 20）/ 全队拿辣椒（溅射 5）** 太超模了。调整：

| 改动 | 内容 |
|---|---|
| **削弱小兽/爬行** | 1 档只给**最前排**（不再全队），全队要凑到 4 只 |
| **加强虫豸/巨兽** | 虫豸 +1/+3 → **+3/+7** 生命；巨兽 +1/+3 → **+2/+5** 攻击 |
| **水生/飞禽** | 水生 +2 → **+3**；飞禽 +1/+1 → **+2/+2**（1 档也从随机 1 个改成 2 个）|
| **新增 🦴 史前**（11 只）| 玻璃大炮：全体 +4/+8 攻击、−2/−3 生命（不会减死）|
| **新增 🐒 灵长**（5 只）| 唯一按**等级**缩放的阵营：全体 +等级/+等级 —— 和「同名合成升级」的核心玩法呼应 |

同时把**门槛统一**成 2/4（灵长因为只有 5 只，用 2/3），
这样「2 只 vs 2 只」时所有阵营都处于 1 档，比较起来才公平。

平衡结果见上面「羁绊平衡实测」—— **8 个阵营全部落在 49.4%~50.5%**。

#### 🎯 胜率重新定标

羁绊变强会**同时**抬高玩家和幽灵的战力，但玩家会主动凑羁绊、幽灵只是随机生成，

### 实测反馈修复 · 第三批（第 17 轮）

#### 🐛「宠物死了尸体还在打」—— 真的存在，但不是引擎的问题

先用插桩排除了引擎：4000 场战斗、3000 场日志分析，
**「已阵亡的宠物还在攻击 / 掉血 / 被加属性」全是 0 处**
（只有 `faint`/`hurt` 在阵亡后触发，那是**遗言本身**，属预期）。

问题在**回放的显示时机**。引擎的 `attack` 事件**自带伤害**，
所以回放里血量在这一步就掉到 0 了，但 `_dead` 标记要等好几条事件之后的
`faint` 才打上 —— 中间那些 `ability`（遗言/受伤/击倒触发）步骤里，
这具 0 血的"尸体"还杵在场上。量化了一下：**最长停留 30 步**（约 12 秒）。

修法：血量一归零就**立刻打 `_dead` 标记**（`markDeadIfZero`），
但真正移出数组仍在下一步开头做 —— 这样 `summon` 的插入位置依然和引擎对齐。
修完实测：**全部只停留 1 步**（就是那一帧阵亡动画）。
新增 `corpse_test.js` 守住这条（1500 场回放 + 断言）。

#### 🐛 商店显示 3 金、实际只收 2 金

`ui.js`（经典模式）**自己手写了一份**商店卡片，价格**硬编码成「3 金」**，
而实际收费走 `petCostOf(defId, g)`（会减掉遗物「批发商」的 1 金折扣）——
所以抽到批发商之后，界面显示 3 金、实际只扣 2 金，玩家会以为扣错钱。

> 这和第 15 轮的「道具图标全是西瓜」是**同一类错误**：经典模式有自己一份重复实现。
> 已经统一改用共用的 `shopPetSlot()`，三个模式一份代码。

官方原文：*"Pets will **sell for one at level 1, for 2 at level 2, and 3 at level three**"*。

#### 第 13 轮顺手修的两个既有 bug

1. **减伤 Perk 挡技能伤害时不会被消耗**（西瓜/大蒜/椰子都中招）。
   以前只有 `exchange()`（普通攻击）会调 `consumeDefensive()`，而技能伤害走的
   是 `hit()` —— 于是**西瓜能无限次挡掉技能伤害**。实测：给一只宠物西瓜，
   连打两次 10 点技能伤害，两次都被减到 0 而西瓜还在。
   现在 `calcDamage()` 会记下「这一次实际生效的是哪个 Perk」，`hit()` 精确消耗它。
   （精确消耗还有个好处：桉树叶挡不了友方伤害时，不会白白浪费掉。）

2. **两个宠物的中文名撞了**：`Pigeon`/`Dove` 都叫「鸽子」、`Rat`/`Mouse` 都叫
   「老鼠」。改成 Dove=**斑鸠**、Mouse=**小鼠**，并加了一条测试专门查重名。

### 商店阶段的遗言（第 11 轮）

安眠药（Sleeping Pill，龟包，1 金）会让一只宠物阵亡并永久移出队伍，
但**会触发它的遗言** —— 也就是要在**商店阶段**跑一遍战斗用的遗言逻辑。
为此给 `ShopEnv` 补齐了一整套战斗兼容 API（`grantExp` / `foes` / `within` /
`hitWithin` / `kill` / `notifyPerkGained` / `inflictWeak`），于是：

- **安眠药**：可以对任意友方使用，触发遗言后移出队伍
- **鼠妇**：出售时库存 N 个免费安眠药（⚠️ 商店只有 2 个食物位，3 级实际只留得下 2 个）
- **螳螂**：回合开始击倒两侧相邻友方，自己 +2/+4/+6 ……
  ⚠️ 官方规则是「**没有友方可以击倒时不触发**」，加成多少与倒了几只无关

### 阵营 / 羁绊（自创机制）

⚠️ **官方没有这个机制**，是为了增加阵容搭配深度自己加的。不喜欢可以无视，
它不会破坏任何原有玩法。

每只宠物属于一个**阵营**。队伍里凑够**同一个阵营的【不同】宠物**就激活加成。
一共 **8 个阵营**：

| 阵营 | 人数 | 2 只（1 档） | 第 2 档 |
|---|---|---|---|
| 🐜 虫豸 | 14 | 开战：全体 +3 生命 | 4 只：全体 +7 生命 |
| 🐟 水生 | 21 | 开战：**最前排** +3/+3 | 4 只：全体 +3/+3 |
| 🐦 飞禽 | 26 | 每回合开始：随机 2 个 +2/+2 | 3 只：全体 +2/+2 |
| 🐘 巨兽 | 27 | 开战：全体 +2 攻击 | 4 只：全体 +5 攻击 |
| 🐾 小兽 | 25 | 开战：**最前排**获得西瓜 | 4 只：全体获得西瓜 |
| 🦎 爬行 | 9 | 开战：**最前排**获得辣椒 | 4 只：全体获得辣椒 |
| 🦴 史前 | 11 | 开战：全体 +4 攻击、−2 生命 | 4 只：+8 攻击、−3 生命 |
| 🐒 灵长 | 5 | 开战：全体 +等级/+等级 | 3 只：+（等级×2） |

游戏页顶部有一条**阵营条**，显示每个阵营的人数、当前档位、以及已激活的效果。
宠物卡片上也有**阵营徽章**；点徽章或阵营条上的任意阵营，会弹出它的
**每档效果 + 包含哪些宠物（队里已有的高亮）+ 你队里凑了几个**。

几个刻意的设计决定：

- **按「不同宠物」计数，不按只数**。否则 3 只同名蚂蚁也能凑满，而 SAP 里同名
  是会合成升级的，按只数会被滥用。按 `defId` 去重才算真实阵容强度。
- **已经有 Food Perk 的宠物不会被覆盖**。小兽和爬行发的 Perk 只给「没带 Perk 的」，
  和遗物「铁甲」同一原则 —— 不然会把玩家自己买的西瓜顶掉。
- **数值按「凑齐难度」定**：成员越少越难凑，效果就给得越强。
  所以成员只有 5 只的**灵长**、14 只的**虫豸**最强，成员 27 只的**巨兽**最弱。
- **小兽和爬行的 1 档只保护最前排**，想要全队得凑 4 只。
  ⚠️ 这两条是第 16 轮**削弱**的：原来是「2 只就全队拿西瓜 / 辣椒」——
  2 只的低门槛 + 全队减 20 / 全队溅射 5，实测明显压过其他阵营（用户反馈也印证了）。

#### 羁绊平衡实测（8 个阵营两两对战）

验收标准：每个阵营的胜率都落在 **40%-60%**。

#### 实测数据（400 局 × 每种策略）

#### 实测数据（400 局 × 每种策略，龟包）

| 策略 | 无阵营 | 有阵营 |
|---|---|---|
| 不特意合宠 | 9% | **19%** |
| 专凑一个阵营 | — | **11%** |

**两个结论**：

1. **阵营大约值 +10 个百分点** —— 这是"有意识地凑"带来的收益，属于设计意图内。
   （单独跑 `balance.js` 时注意到：这份测试 AI 比 `winrate.js` 里那个弱，
   所以绝对值偏低；**看相对差距就好**，绝对难度以 `winrate.js` 为准。）
2. **「专凑一个阵营」反而更差**（11% vs 19%）—— 说明它有真实的取舍成本：
   为了凑阵营会放弃更好的宠物和合宠机会。这是好信号，不是白送。

⚠️ 上表是**龟包**数据（`CFG.PACK='turtle'`）。龟包是基础包，8 个阵营的成员分布很不均
（史前/灵长/爬行在龟包里几乎凑不到），星包的分布会均衡得多。

实测里各阵营被激活的次数差了两个数量级（同样是龟包、400 局累计）：

| 阵营 | 激活次数 | 特点 |
|---|---|---|
| 🐜 虫豸 | 661 ~ 1993 | 低阶最密集，**开局就能凑**，也是最好凑的之一 |
| 🐦 飞禽 | 493 ~ 805 | 中低阶都够 |
| 🐾 小兽 | 432 ~ 785 | T1 就有好几只 |
| 🐘 巨兽 | 292 ~ 468 | 中高阶为主（成员最多但偏后期） |
| 🐟 水生 | 43 ~ 92 | 龟包低阶只有鱼和螃蟹，**偏中后期** |
| 🦎 爬行 / 🦴 史前 / 🐒 灵长 | 龟包几乎为 0 | 成员基本都在星包；**这是有意的**（难度换强度） |

> 龟包里爬行只有乌龟/鳄鱼(T4-T5)/蛇/龙(T6)，所以想在龟包吃爬行羁绊是很后期的事；

但如果你希望每个阵营都能早期凑起来，那需要从低阶宠物里重新划分，我可以再调。

### 种子（同一局 / 分享）

每一局都有一个种子，显示在游戏页顶部。**同一个种子 + 同样的操作 = 完全相同的一局**
（商店、对手、战斗过程全都逐条一致）。

| 想干嘛 | 怎么做 |
|---|---|
| 玩别人分享的一局 | 打开 `solo.html?seed=ABC123`（顶部也会显示这个种子） |
| 把好玩的一局发给朋友 | 点顶部「🔗 分享这局」，复制链接 |
| 手动换一个种子 | 点「✏️ 换种子」，输入即可 |
| 玩今天的每日挑战 | 主页点「📅 每日挑战」，或打开 `solo.html?daily=1` |

⚠️ 说清楚"同种子"到底保证什么：它保证**随机数的来源相同**。
所以只要两个人做的操作一样（买哪只、刷几次），看到的就是同一局；
一旦有人多刷了一次商店，之后的随机序列就会岔开 —— 这和《杀戮尖塔》那类
种子游戏的语义是一样的，不是 bug。

联机的种子由**服务器**决定（顶部显示 `房间种子`），所有人用同一条随机流。
服务器也支持固定种子启动：`node server.js --seed=ABC123`。

   会弹出一个黑窗口，里面写着两个地址：
   ```
   自己玩（本机）:   http://localhost:8000
   发给朋友（局域网）: http://192.168.x.x:8000   [WLAN]
   ```
2. **其他人**：手机/电脑连**同一个 WiFi**，浏览器打开那个 `192.168.x.x` 地址。
   不用装任何东西，手机也能直接玩。
3. 每人输入昵称 → 加入房间 → 房主点「开始游戏」。
   人不够没关系，**空位自动由电脑补位**（1 个人也能开一局练手）。
4. **那个黑窗口不能关**，关了大家就掉线。

> **双击 `开服.bat` 一闪而过？** 说明批处理没能把服务器拉起来。最可能的原因是没装 Node.js
> 或者没在 PATH 里 —— 打开命令行输入 `node -v`，能打印版本号才算装好。
> 想看到真正的报错：在文件夹里打开命令行执行 `node server.js`，报错就会留在窗口里。

> **给将来改这个文件的人**：`开服.bat` 必须保持**纯 ASCII**。
> cmd.exe 是按系统 ANSI 代码页（中文 Windows 是 GBK）读批处理文件的，不是 UTF-8。
> 一旦里面写了 UTF-8 中文，某个字的尾字节会被当成 GBK 双字节的第二个字节，
> **把行尾的换行吃掉** —— 结果 `node server.js` 那行被并进上面的 `REM` 注释里，
> 服务器根本没启动，窗口一闪就退（而且不报任何错）。
> 所有面向用户的中文提示都由 `server.js` 打印（Node 输出到控制台是 Unicode，没问题）。

几个实用细节：

- **谁当主持人都行**，不一定是你。服务器就是主持人电脑上的一个普通程序，不花钱、不上外网。
- **有人挂机怎么办**：房主可以点「⏭ 强制开打」，服务器会替没准备的人用电脑打完这一回合。
- **刷新页面不会掉线**：凭证存在浏览器里，刷新后自动回到自己的座位（房间重置才需要重新加入）。
- **出局后还能观战**，看完剩下的人打完，也能看到自己拿了第几名。

### 遗物系统

每 3 回合（从回合 3 开始）给你一次**三选一**的机会，选中的遗物**永久生效**，两种模式都有。

目前共 **13 种**，分三类：

| 类型 | 遗物 |

| ⚔️ 战斗 | 战旗（开战全体+4生命）、獠牙（开战全体+2攻击）、铁甲（开战全体获得椰子）、猎杀标记（开战对敌方最前排 3 伤害）、急救包（开战全体+2生命） |

### 通用规则

- 队伍上限随回合增长：**回合 1-2 最多 3 只、回合 3-4 最多 4 只、回合 5+ 最多 5 只**
- 买**同名**宠物会合成升级：`2 点经验 → 2 级`，`再 3 点经验 → 3 级`（每点经验 **+1/+1**）
- **商店等级**按回合自动解锁：**回合 1→T1、3→T2、5→T3、7→T4、9→T5、11+→T6**
  （商店只会刷出已解锁星级的宠物）
- **升星奖励**（官方规则）：宠物升星时，商店里会出现 **2 个「下一星级」的宠物**供你挑选；
  但**合成到 3 级不触发**

## 战斗机制（引擎的核心）

引擎严格按 SAP 官方规则实现：

1. **攻击是「双方同时互殴」**，不是先手制。
   每个战斗回合，双方最前排的宠物**同时**对彼此造成伤害。
2. **伤害 = 攻击力**，最低 1 点；有西瓜时可减到 0，椰子可完全免疫一次。
3. **阶段顺序**：
   `开战 → 攻击前 → 互殴 → 受伤/阵亡 → 攻击后 → 后排见证 → 回合结束`
4. **宠物阵亡后从队伍移除，后排补位**。
5. **遗言链会递归结算**：一个宠物的阵亡触发的召唤/伤害，可以继续引发新的阵亡。
6. **Perk 只能带一个**（官方规则）：宠物同时只能携带 1 个食物 Perk，新的会覆盖旧的。

## 对手与难度

### 经典模式：官方 Ghost（幽灵）算法

对手队伍按官方 wiki 的 Ghost 规则生成：

- **回合 1**：从 Tier 1 选 **3 只**
- **回合 2+**：选 5 只（不超过当回合队伍上限），并获得**行动点**
- **行动点 = 回合数 × 2 − 4**，每点随机做三件事之一：
  ① 给一只宠物一个食物 Perk　② 给一只宠物 +1 经验
  ③ 给一只宠物 +`floor(回合/4)+2` 点属性（随机分到攻击或生命）

**注意**：官方没有显式难度系数——难度差异来自**行动点的随机分配**（有的幽灵属性堆在一只身上，有的摊得很散），这天然产生强弱差异。

> ⚠️ **本作对行动点打了 `0.60` 的折扣**（`CFG.AP_SCALE`）。因为官方曲线是给「完整 6 tier 宠物池 + 真实玩家快照」设计的，而本作只有 Turtle Pack 61 只、对手全是幽灵，按原版会碾压玩家。
>
> **这个值对羁绊强度非常敏感，每次动羁绊都要重测。** 第 15 轮时它是 `0.42`（通关率 22%），
> 第 16 轮加了 2 个阵营、调强了数值之后，同样的 `0.42` 直接涨到 **34%** ——
> 因为玩家会主动凑羁绊，而幽灵只是随机生成。重新定标后才改成 `0.60`。
>
> 定标方法（`winrate.js`）：一个「会同名合成 + 买食物 + 凑阵营」的普通水平 AI，
> 每档 500 局、固定种子。实测 `0.55→28% · 0.58→25% · 0.60→23% · 0.65→21% · 0.85→16%`，
> 目标是 **20-25%**。

### 8 人混战

- **7 个人机与你使用完全相同的商店规则**（保证公平）
- 每个人机有**随机性格**（`greed` 0.55~0.95）：有人激进花钱、有人攒钱吃利息，天然强弱有别
- 每回合随机两两配对；**人数为奇数时随机一人轮空**（不掉血）
- 扣血 = `基础伤害(随回合增长) + 每个存活敌方单位 1 点`

### 五条关键设计

**1. 引擎输出「有序事件日志」，而不是最终状态**

引擎跑完一场战斗，返回的不是"谁赢了"，而是一串事件：

```js
{ e:'attack', a:uid, b:uid, dmgA:3, dmgB:1 }
{ e:'faint',  t:uid, pos:0 }
{ e:'summon', t:uid, side:0, pos:0, defId:'ZombieCricket' }
```

界面拿着这串事件**逐条播放**，于是血条、动画、召唤都自然发生。
**战斗回放功能是白送的**，8 人模式里 AI 之间的战斗则可以只取结果、丢掉日志（所以 8 人局不会卡）。

**2. 技能是数据，引擎不认识任何具体宠物**

引擎只提供通用原语（`buff` / `hit` / `summon` / `behind` / `ahead` …），
每个宠物的技能写成一小段数据：

```js
Ant: {
  name: 'Ant', cn: '蚂蚁', tier: 1, atk: 2, hp: 2,
  texts: ['阵亡：给随机 1 个友方 +1/+1', '…+2/+2', '…+3/+3'],
  hooks: {
    faint: (g, c) => {
      const t = g.random(g.friends(c.self), 1);
      if (t[0]) g.buff(t[0], c.lvl, c.lvl);
    }
  }
}
```

**加一只新宠物 = 加一条数据，不用改引擎。**

**3. 公共渲染层**

`render.js` 里只有无状态的纯函数（宠物卡、商店槽、道具槽、遗物条、**图鉴**）。
加新玩法时，复制一份 `solo.html` + 写自己的 js 即可，渲染全部复用。

图鉴就是一个例子：`renderCodexInto(bodyEl, subEl)` 负责把宠物 / 召唤物 / 道具 / 遗物
全部渲染进指定容器，两种模式只是各自传一个遮罩层的选择器，
所以**新增遗物会自动出现在两个模式的图鉴里**，不需要改两处。

**4. 联机：服务器当裁判，浏览器只负责显示**

联机最麻烦的是"两端算出不同结果"。这里绕开了这个问题，靠的是引擎本来就有的两个特性：

- **战斗不可能不同步**：战斗结果不是两端各算一遍，而是**服务器算完，把事件日志发过去，客户端照着播**。
  日志里的 `uid` 直接对应快照里的宠物，所以没有任何"重算"环节可以出错。
- **加宠物/改数值不用动联机**：`js/online.js` 不复制任何规则，
  它 `require` 的是**同一份** `game.js` / `engine.js` / `relics.js`
  （通过 `js/node-loader.js` 把它们装进一个作用域 —— 这些文件在浏览器里靠 `<script>` 顺序共享全局，
  单独 `require` 会 `ReferenceError`）。
  连 AI 经营都是直接借用 `Melee.prototype.aiShop`，因为它内部不使用 `this`。

状态同步的方式很朴素：服务器把**你自己那份** `Game` 序列化发给你
（`pack.js`：只存 `defId`，解包时查 `PETS` 还原；**绝不重新 `makePet`**，否则 uid 会对不上回放日志）。

一个容易忽略的点：**单机模式完全没被联机污染**。
`melee.js` 写死了"1 个人类 + 7 个 AI"，联机的 8 个座位语义不同，
所以流程单独写在 `online.js` 里，两边共用 `MELEE_CFG`（数值只改一处）。
服务器只在有人联机时才需要启动，平时双击 `index.html` 一个进程都不用开。

**5. 所有随机都走一个可控的随机源**

项目里原本有 18 处直接调 `Math.random()`，散在 6 个文件里。问题不是"能不能用"，
而是**出了 bug 没法复现** —— 只能反复重试等它出现；测试也只能跑很多局碰运气。

现在全部走 `rng.js`：`RNG.seed('ABC123')` 之后，同样的操作一定得到同样的一局。
这一次改动同时解锁了四件事：每日挑战、把种子发给朋友、bug 可复现、
以及**测试变成确定性的**（`seed.js` 就是拿两个同种子的整局做逐条比对，
连战斗日志都要一致）。

唯一刻意**不**受种子影响的随机是联机凭证 token —— 所有玩家的 token 必须有区别，
不能因为同一个种子撞在一起。

## 部署到公网（发链接让别人玩）

这个项目是**纯静态**的（无构建、无依赖、无后端），所以随便丢到哪个静态托管都能跑：

1. 把整个文件夹（或仓库）上传到 GitHub Pages / Netlify / Vercel / 自己的 Web 服务器
2. 把首页链接发出去，别人点开就能玩单机模式

**注意：公网链接上不能联机。** 联机需要一台会算游戏的服务器，静态托管只发文件。
所以首页会自动探测 `/api/ping`：

- 探测到 → 显示「🌐 联机混战」入口
- 探测不到 → 只显示两个单机模式，并在页脚提示"想联机请让主机双击 开服.bat"

用 GitHub Pages 的话，仓库里已经放好了 `.nojekyll`（跳过 Jekyll 处理）。
另外提醒一句：**GitHub Pages 的链接是公开的**，拿到链接的人都能玩。
