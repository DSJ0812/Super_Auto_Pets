# Super Auto Pets · 单机 + 局域网联机

一个纯前端的 Super Auto Pets 复刻。**双击 `index.html` 就能玩**，不需要安装任何东西。
想和朋友一起玩时，双击 `开服.bat` 就能开一个局域网房间。

---

## 怎么玩

### 三种打开方式

| 你想干嘛 | 怎么做 | 要服务器吗 |
|---|---|---|
| **自己玩** | **双击 `index.html`** → 选模式 → 开玩 | 不要 |
| **和朋友在同一局里玩** | 主机双击 **`开服.bat`** → 把它显示的局域网地址发给大家 → 大家浏览器打开加入房间 | 要（就是主持人的电脑） |
| **发个链接让别人自己玩** | 把这个文件夹传到任意静态托管，把链接发出去 | 不要 |

第三种之所以不需要服务器：单机模式本来就是纯静态的。但**公网链接上不能联机** ——
联机需要一个"大家一起连的服务器"，公网静态托管只发文件、不会算游戏。
所以主页会自动探测：探测到服务器才显示「🌐 联机混战」入口。

### 三种模式

| 模式 | 玩法 | 经济 |
|---|---|---|
| **🎯 经典模式** | **10 胜**通关、**3 败**出局（平局不算输）。每回合打一支系统生成的对手队伍 | **SAP 式**：每回合固定 10 金，**不累积**；宠物统一 3 金；刷新 1 金 |
| **⚔️ 8 人混战** | 你和 **7 个人机**同场竞技。每回合随机两两配对，输的扣血，**血量归零出局**；活到最后获胜 | **TFT 式**：基础 5 金 + **利息**（每存满 10 金 +1，上限 5）+ **连胜奖励**（分档 +1/+2/+3），金币**累积**；宠物**按星级定价** T1=1 金 … T6=6 金；刷新 2 金 |
| **🌐 联机混战** | 8 人混战，但**其他座位可以是真人**。人不够时剩下的座位由电脑补位 | 同 8 人混战 |

### 联机怎么用

1. **主持人的电脑**：双击 `开服.bat`（需要装 [Node.js](https://nodejs.org)，只装一次）。
   macOS / Linux 或者不想用 bat 的话，在文件夹里执行 `node server.js` 也一样（换端口：`node server.js 8080`）。
   会弹出一个黑窗口，里面写着两个地址：
   ```
   自己玩（本机）:   http://localhost:8000
   发给朋友（局域网）: http://192.168.x.x:8000   [WLAN]
   ```
2. **其他人**：手机/电脑连**同一个 WiFi**，浏览器打开那个 `192.168.x.x` 地址。
   不用装任何东西，手机也能直接玩。
3. 每人输入昵称 → 加入房间 → 房主点「开始游戏」。
   人不够没关系，**空位自动由电脑补位**（1 个人也能开一局练手）。
4. **那个黑窗口不能关**，关了大家就掉线。

> **双击 `开服.bat` 一闪而过？** 说明批处理没能把服务器拉起来。最可能的原因是没装 Node.js
> 或者没在 PATH 里 —— 打开命令行输入 `node -v`，能打印版本号才算装好。
> 想看到真正的报错：在文件夹里打开命令行执行 `node server.js`，报错就会留在窗口里。

> **给将来改这个文件的人**：`开服.bat` 必须保持**纯 ASCII**。
> cmd.exe 是按系统 ANSI 代码页（中文 Windows 是 GBK）读批处理文件的，不是 UTF-8。
> 一旦里面写了 UTF-8 中文，某个字的尾字节会被当成 GBK 双字节的第二个字节，
> **把行尾的换行吃掉** —— 结果 `node server.js` 那行被并进上面的 `REM` 注释里，
> 服务器根本没启动，窗口一闪就退（而且不报任何错）。
> 所有面向用户的中文提示都由 `server.js` 打印（Node 输出到控制台是 Unicode，没问题）。

几个实用细节：

- **谁当主持人都行**，不一定是你。服务器就是主持人电脑上的一个普通程序，不花钱、不上外网。
- **有人挂机怎么办**：房主可以点「⏭ 强制开打」，服务器会替没准备的人用电脑打完这一回合。
- **刷新页面不会掉线**：凭证存在浏览器里，刷新后自动回到自己的座位（房间重置才需要重新加入）。
- **出局后还能观战**，看完剩下的人打完，也能看到自己拿了第几名。

### 遗物系统

每 3 回合（从回合 3 开始）给你一次**三选一**的机会，选中的遗物**永久生效**，两种模式都有。
8 人混战里 7 个人机会随机拿一个（保证规则对等）。

目前共 **13 种**，分三类：

| 类型 | 遗物 |
|---|---|
| 💰 经济 | 金库（+3金/回合）、钱庄（利息上限+3）、批发商（宠物-1金）、营养师（食物-1金）、当铺（出售+1金） |
| ⭐ 成长 | 训练场（每回合给最前友方+1/+1）、孵化器（升星奖励变 3 个）、星探（商店等级提前 1 回合） |
| ⚔️ 战斗 | 战旗（开战全体+4生命）、獠牙（开战全体+2攻击）、铁甲（开战全体获得椰子）、猎杀标记（开战对敌方最前排 3 伤害）、急救包（开战全体+2生命） |

忘了某个遗物干什么？点右上角「📖 图鉴」拉到最下面，遗物按类别分组、带类别色标。

### 通用规则

- 队伍上限随回合增长：**回合 1-2 最多 3 只、回合 3-4 最多 4 只、回合 5+ 最多 5 只**
- 买**同名**宠物会合成升级：`2 点经验 → 2 级`，`再 3 点经验 → 3 级`（每点经验 **+1/+1**）
- **商店等级**按回合自动解锁：**回合 1→T1、3→T2、5→T3、7→T4、9→T5、11+→T6**
  （商店只会刷出已解锁星级的宠物）
- **升星奖励**（官方规则）：宠物升星时，商店里会出现 **2 个「下一星级」的宠物**供你挑选；
  但**合成到 3 级不触发**

## 战斗机制（引擎的核心）

引擎严格按 SAP 官方规则实现：

1. **攻击是「双方同时互殴」**，不是先手制。
   每个战斗回合，双方最前排的宠物**同时**对彼此造成伤害。
2. **伤害 = 攻击力**，最低 1 点；有西瓜时可减到 0，椰子可完全免疫一次。
3. **阶段顺序**：
   `开战 → 攻击前 → 互殴 → 受伤/阵亡 → 攻击后 → 后排见证 → 回合结束`
4. **宠物阵亡后从队伍移除，后排补位**。
5. **遗言链会递归结算**：一个宠物的阵亡触发的召唤/伤害，可以继续引发新的阵亡。
6. **Perk 只能带一个**（官方规则）：宠物同时只能携带 1 个食物 Perk，新的会覆盖旧的。

## 对手与难度

### 经典模式：官方 Ghost（幽灵）算法

对手队伍按官方 wiki 的 Ghost 规则生成：

- **回合 1**：从 Tier 1 选 **3 只**
- **回合 2+**：选 5 只（不超过当回合队伍上限），并获得**行动点**
- **行动点 = 回合数 × 2 − 4**，每点随机做三件事之一：
  ① 给一只宠物一个食物 Perk　② 给一只宠物 +1 经验
  ③ 给一只宠物 +`floor(回合/4)+2` 点属性（随机分到攻击或生命）

**注意**：官方没有显式难度系数——难度差异来自**行动点的随机分配**（有的幽灵属性堆在一只身上，有的摊得很散），这天然产生强弱差异。

> ⚠️ **本作对行动点打了 `0.4` 的折扣**（`CFG.AP_SCALE`）。因为官方曲线是给「完整 6 tier 宠物池 + 真实玩家快照」设计的，而本作只有 Turtle Pack 61 只、对手全是幽灵，按原版会碾压玩家。实测折扣 0.4 时通关率约 40%（测试 AI 是下限，真人会更高）。

### 8 人混战

- **7 个人机与你使用完全相同的商店规则**（保证公平）
- 每个人机有**随机性格**（`greed` 0.55~0.95）：有人激进花钱、有人攒钱吃利息，天然强弱有别
- 每回合随机两两配对；**人数为奇数时随机一人轮空**（不掉血）
- 扣血 = `基础伤害(随回合增长) + 每个存活敌方单位 1 点`

### 三条关键设计

**1. 引擎输出「有序事件日志」，而不是最终状态**

引擎跑完一场战斗，返回的不是"谁赢了"，而是一串事件：

```js
{ e:'attack', a:uid, b:uid, dmgA:3, dmgB:1 }
{ e:'faint',  t:uid, pos:0 }
{ e:'summon', t:uid, side:0, pos:0, defId:'ZombieCricket' }
```

界面拿着这串事件**逐条播放**，于是血条、动画、召唤都自然发生。
**战斗回放功能是白送的**，8 人模式里 AI 之间的战斗则可以只取结果、丢掉日志（所以 8 人局不会卡）。

**2. 技能是数据，引擎不认识任何具体宠物**

引擎只提供通用原语（`buff` / `hit` / `summon` / `behind` / `ahead` …），
每个宠物的技能写成一小段数据：

```js
Ant: {
  name: 'Ant', cn: '蚂蚁', tier: 1, atk: 2, hp: 2,
  texts: ['阵亡：给随机 1 个友方 +1/+1', '…+2/+2', '…+3/+3'],
  hooks: {
    faint: (g, c) => {
      const t = g.random(g.friends(c.self), 1);
      if (t[0]) g.buff(t[0], c.lvl, c.lvl);
    }
  }
}
```

**加一只新宠物 = 加一条数据，不用改引擎。**

**3. 公共渲染层**

`render.js` 里只有无状态的纯函数（宠物卡、商店槽、道具槽、遗物条、**图鉴**）。
加新玩法时，复制一份 `solo.html` + 写自己的 js 即可，渲染全部复用。

图鉴就是一个例子：`renderCodexInto(bodyEl, subEl)` 负责把宠物 / 召唤物 / 道具 / 遗物
全部渲染进指定容器，两种模式只是各自传一个遮罩层的选择器，
所以**新增遗物会自动出现在两个模式的图鉴里**，不需要改两处。

**4. 联机：服务器当裁判，浏览器只负责显示**

联机最麻烦的是"两端算出不同结果"。这里绕开了这个问题，靠的是引擎本来就有的两个特性：

- **战斗不可能不同步**：战斗结果不是两端各算一遍，而是**服务器算完，把事件日志发过去，客户端照着播**。
  日志里的 `uid` 直接对应快照里的宠物，所以没有任何"重算"环节可以出错。
- **加宠物/改数值不用动联机**：`js/online.js` 不复制任何规则，
  它 `require` 的是**同一份** `game.js` / `engine.js` / `relics.js`
  （通过 `js/node-loader.js` 把它们装进一个作用域 —— 这些文件在浏览器里靠 `<script>` 顺序共享全局，
  单独 `require` 会 `ReferenceError`）。
  连 AI 经营都是直接借用 `Melee.prototype.aiShop`，因为它内部不使用 `this`。

状态同步的方式很朴素：服务器把**你自己那份** `Game` 序列化发给你
（`pack.js`：只存 `defId`，解包时查 `PETS` 还原；**绝不重新 `makePet`**，否则 uid 会对不上回放日志）。

一个容易忽略的点：**单机模式完全没被联机污染**。
`melee.js` 写死了"1 个人类 + 7 个 AI"，联机的 8 个座位语义不同，
所以流程单独写在 `online.js` 里，两边共用 `MELEE_CFG`（数值只改一处）。
服务器只在有人联机时才需要启动，平时双击 `index.html` 一个进程都不用开。

## 部署到公网（发链接让别人玩）

这个项目是**纯静态**的（无构建、无依赖、无后端），所以随便丢到哪个静态托管都能跑：

1. 把整个文件夹（或仓库）上传到 GitHub Pages / Netlify / Vercel / 自己的 Web 服务器
2. 把首页链接发出去，别人点开就能玩单机模式

**注意：公网链接上不能联机。** 联机需要一台会算游戏的服务器，静态托管只发文件。
所以首页会自动探测 `/api/ping`：

- 探测到 → 显示「🌐 联机混战」入口
- 探测不到 → 只显示两个单机模式，并在页脚提示"想联机请让主机双击 开服.bat"

用 GitHub Pages 的话，仓库里已经放好了 `.nojekyll`（跳过 Jekyll 处理）。
另外提醒一句：**GitHub Pages 的链接是公开的**，拿到链接的人都能玩。

## 加自己的宠物

在 `js/data.js` 的 `PETS` 里加一条即可。可用的 `hooks`：

| 阶段 | hook | 上下文 |
|---|---|---|
| 战斗 | `startOfBattle` | 开战时 |
| 战斗 | `beforeAttack` | 自己即将攻击 |
| 战斗 | `selfAttack` | 自己攻击后 |
| 战斗 | `hurt` | 自己受伤（`c.dmg`） |
| 战斗 | `knockOut` | 自己击倒敌人（`c.target`） |
| 战斗 | `afterAttack` | 自己攻击结算完毕 |
| 战斗 | `aheadAttack` | 前面的队友攻击了 |
| 战斗 | `aheadFaint` | 前面的队友阵亡了 |
| 战斗 | `friendFaints` | 任意友方阵亡（`c.dead`） |
| 战斗 | `friendHurt` | 任意友方受伤（`c.hurt`） |
| 战斗 | `faint` | 自己阵亡（遗言） |
| 战斗 | `friendSummoned` | 友方被召唤（`c.target`） |
| 战斗 | `summoned` | **自己**被召唤 |
| 商店 | `buy` / `sell` / `levelUp` | 买 / 卖 / 升级时 |
| 商店 | `startTurn` / `endTurn` | 回合开始 / 结束 |
| 商店 | `friendlyAteFood` | 友方吃了道具（`c.eater`） |
| 商店 | `friendBought` | 友方被购买（`c.bought`） |

可用原语：`g.buff(pet, atk, hp)`、`g.hit(pet, n)`、`g.summon(side, pos, defId, {atk, hp, lvl})`、
`g.friends(pet)`、`g.foes(pet)`、`g.behind(pet, n)`、`g.ahead(pet, n)`、`g.random(arr, n)`、
`g.givePerk(pet, 'Melon')`、`g.addGold(n)`、`g.stock('Apple', 0)`

  （攻击同时结算、触发分层、阵亡塌缩、伤害上下限）。

- **商店等级 / 升星奖励 / Ghost 算法**：均取自官方 wiki「The Basics」与「Ghost」页面。
